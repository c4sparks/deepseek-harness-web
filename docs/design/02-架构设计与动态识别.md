# 02 · 架构设计与动态识别

> 阶段：设计 · 维护者：插件维护者

## 分层
单向依赖 UI → 服务 → API，UI 可换、协议可换。

| 层 | 载体 | 职责 | 可替换 |
|---|---|---|---|
| 装配 | extension.ts | 命令/面板/桥接 | 只加命令 |
| UI | webview/chat、`dshPanel.ts`（官方网页面板） | 聊天、内嵌 dsh 网页 | 可整体换 |
| 服务 | api/dshService.ts | dsh 进程/会话/对话编排 | 稳定接口 |
| 事件 | dsh/events.ts | $events 监听流与应答回传 | 只依赖 dsh 门面 |
| API | dsh/{auth,rpc,mux,session,stream,legacy,agentPresets}（api.ts/index.ts 门面；agentPresets 于 v0.1.4 · dsh 0.1.2-rc.1 新增） | dsh 协议层 | 换后端只改 dsh/ |

数据流：UI → extension → dshService → dsh/（rpc 信封、mux WS、session/stream、events、webProxy、agentPresets）→ dsh；事件投影返回 → postMessage → UI。

## 服务层接口（聊天 UI 依赖）
| 类别 | 方法 | 说明 |
|---|---|---|
| 通用 | call(method, payload) | 任意 dsh API |
| 进程 | ensureRunning / dispose | 启动/复用/回收；ensureRunning 单飞，并发入口共享同一次启动 |
| 会话 | getSession / newSession / ensureCurrentWorkspace / ensureWorkspaceForFolder | 会话与当前工作区 |
| 工作区 | listWorkspaces / createWorkspace / listWorkspaceSessions / restoreSession | 枚举/新建/恢复 |
| 对话 | ask / askStreaming / approvalResponse / answerQuestion / cancelQuestion | 发送/流式/审批/提问/停止 |
| 模型/权限 | listModels / selectModel / setPermissionPreset | 模型/权限 |
| 投影 | getProjections | 官方投影 |

官方网页面板 UI 由 `src/dshPanel.ts`（openPanel/openInBrowser/openInEditor/reloadPanels/viewMode）提供，通过宿主 `ensureRunning()` 使用 DshService；关闭面板只回收本地代理，不回收 dsh 进程。

## 技术选型
VS Code 扩展（vscode>=1.110，node ^22.19\|\|>=24）+ 原生 webview(无框架) + esbuild(产物 dist/extension.js) + scripts/build-chat.mjs(产物 dist/chat) + 本机 HTTP JSON-RPC + `/api/remote.mux` WS + 会话归 dsh + 仅 `globalState['dsh.usage']` 持久化。无数据库。

| 模块 | 职责 | 依赖 |
|---|---|---|
| extension.ts | 装配：命令、聊天 UI、DshPanel | DshService、dsh 门面 |
| dshPanel.ts | 官方网页面板 UI | DshService.ensureRunning、dsh/webProxy |

依赖是单向的：auth → rpc/mux → session → stream；events/webProxy/agentPresets 位于其上层，无循环。

## 动态识别
- 连接模型：`DshEndpoint{port, authUrl}`，默认 `{port:3080}`；`endpointBaseUrl()` 明文、`endpointAuthUrl()` 优先带 token；所有传输从 `currentEndpoint` 取端口。
- 端口发现（ensureRunning 阶段）：① probeDsh(配置/3080)命中复用；② Node 检查；③ 启动器四档回退 cliPath → repoPath(`pnpm dsh web`) → PATH dsh → npx；固定参数 `web --no-open --port 0`（可经 `dsh.webArgs` 追加 `--host`/`--trusted-host` 等）；④ 解析 stdout `dsh web: http://127.0.0.1:PORT?token=…`(正则 `/dsh web: (https?:\/\/[^\s]+)/`)；⑤ 验信封 → ready。90s 未就绪报 stderr 末行并回收；超时回退 3080。
  复用注意：rc.1 手动实例没有 `dsh web` URL 时插件拿不到 authUrl、无法自动登录，因此一般不复用；建议 `dsh.port=0` 让插件自启。
- 握手探测 probeDsh：只读 `session/list`。判定：server-response+ok=可达；server-response+ok=false(DshRpcError)=可达(版本差异)；401/403=需鉴权；其它/非 JSON=端口非 DSH；连接失败=未运行。
- 事件投影：`DSH_EVENT_TYPES` 常量 + `projectHistoryEvent()` 判别联合；dsh 改事件名只改这两处。
- 鉴权：dsh v0.1.2-rc.1 起 `/api`、WS、网页 `/` 都要求 `dsh-auth-*` cookie
  （`?token=` 换 HttpOnly + SameSite=Strict）。Webview iframe 无法保存该 cookie，
  内嵌面板走 `dsh/webProxy.ts` 本地认证代理（扩展进程持有 cookie，转发 HTTP/WS 到真实端口）；
  外部浏览器直接用 `endpointAuthUrl()`。
- 面板代理：打开面板前先 `ensureEndpointAuth()`，再 `startDshWebProxy()`；
  只监听 127.0.0.1 随机端口，iframe 加载代理同源地址；面板全部关闭时只回收代理端口，
  dsh 进程保留到扩展停用（dispose），避免关闭网页面板后聊天再次启动服务。
  代理对上游 401 自动重新登录并重试（无实体请求），仍失败时给可读错误页而不铺上游裸 401。

## 降级
| 场景 | 路径 |
|---|---|
  | RPC 可用 | 自绘聊天 / 官方页本地代理 |
| RPC 不可用 / 鉴权失败 | 报错并引导在浏览器打开 `endpointAuthUrl()` |

## 可插拔
| 层 | 可插拔点 | 机制 |
|---|---|---|
| UI | 聊天整体可换 | 只依赖 DshService |
| 能力 | mux/流式/审批/提问 | `DshCapabilities{mux,streaming}` 门控 |
| 协议 | 后端可换 | 只改 dsh/ 下模块 |

复杂 UI 单元按 `ChatFeature{id,mount,unmount,enabled}` 注册；能力门控读 capability、配置门控读 dsh.port/cliPath/repoPath、危险功能 danger-full-access 需确认。新能力流程：dsh/ 加方法 → dshService 封装(读 capability) → UI 加 feature(读 enabled) → 可选加配置。

## 关键设计点
共享会话（右键/对话/网页同一线）；当前工作区 = workspace/follow updatedAt 最新（不另存）；视图重建握手（webview 发 ready 后扩展再推 chatInfo）。
