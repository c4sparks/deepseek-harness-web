# 05 · 测试、发布与工程

> 阶段：测试/发布 · 维护者：插件维护者

## 构建命令
```bash
# 静态门禁
pnpm run check-types   # tsc --noEmit
pnpm run lint          # eslint src

# 产物构建：dist/chat 与 dist/extension.js
pnpm run build:chat
node esbuild.js        # 生产用: node esbuild.js --production

# 日常 / 生产 / 测试
pnpm run compile       # check-types + lint + build:chat + esbuild
pnpm run package       # 生产构建（vscode:prepublish 触发）
pnpm test              # vscode-test
```

## 打包
```bash
pnpm vsix
```

自动建 release/，完整构建后由 `vsce` 出包。产物含 `dist/extension.js`、`dist/chat/`、`assets/icon.png`；进包内容由 `.vscodeignore` 控制，源码、依赖、文档等默认不打进包。注意仓库根不要残留临时目录，以免被误打进包。

## 改码后出新包（速查，均在仓库根执行）

开发验证（Run Extension / F5）：
```bash
# watch 已开时，源码改动会自动重建 dist/；但扩展宿主不会热加载。
# 每次改完源码都先重载再点按钮：
# Ctrl+Shift+P -> Developer: Reload Window
```

未开 watch 时先手动编译（一句过静态门禁 + 重建产物）：
```bash
pnpm run compile   # check-types + lint + build:chat + esbuild
```

打可分发 VSIX（内部自动先跑全量构建）：
```bash
pnpm vsix          # 产物：release/<name>.vsix
```

装到本机并用新包（同版本也建议加 --force 覆盖）：
```bash
code --install-extension release/<name>.vsix --force
```

装完先重载 VS Code 窗口（`Developer: Reload Window`）再点按钮。

> 注意：工作区的源码或 dist 改动不会自动进入“已安装扩展”。普通 VS Code 里测试必须“重打包 + 重装 + 重载”三件都做，缺一看到的仍可能是旧逻辑。

## 测试
范围：启动/端点发现、RPC、流式、审批/提问、权限(danger)、模型、工作区/会话、右键、消费记录、UI、升级回归。分层：静态 → 集成真机（隔离 DSH_HOME + ?token 逐端点）→ UI 手工 → 升级回归。

用例要点：A01 启动、A02 流式、A03 模型、A04 danger 确认、A05 工作区树、A06 右键、A07 消费记录；边界 B01 长会话、B02 窄面板、B03 切回重建；异常 C01 Node 缺失、C02 端口非 dsh、C03 需鉴权、C04 mux 不可用、C05 端点消失；升级回归 D01 真机探测。

兼容/性能观测（轻量）：长会话内存/卡顿、webview 切回重建、流式不卡 UI。

## 发布
- 版本号：SemVer `MAJOR.MINOR.PATCH`。PATCH 修复/小改、MINOR 新功能、MAJOR 破坏性（如 dsh 协议面不兼容）、预发 `-rc.x`/`-alpha.x`。
- 日常测试同版本新包见上文“改码后出新包”，不必 bump；正式发布才需要 bump 版本并更新仓库根 `CHANGELOG.md` / ReleaseNotes（CHANGELOG 位于仓库根，不随 VSIX 发布）。

```bash
# ① bump package.json 版本
# ② 更新仓库根 CHANGELOG.md / ReleaseNotes（不随 VSIX 发布）
# ③ 打包
pnpm vsix
# ④ 分发：本地安装 或 上架
# code --install-extension <vsix 路径>
# npx @vscode/vsce publish
```

> Access Token 只存本机 `~/.vsce` 或 CI secret，严禁提交仓库/写明文。

## 回滚
```bash
# 先收起 DSH 侧栏 / 关面板，再卸旧装新
code --uninstall-extension <publisher>.<name>
code --install-extension release/<name>-<上一版>.vsix
```
残留多版本冲突：删 `~/.vscode/extensions/<publisher>.<name>-*` 多余目录后重装（卸载报错属 sidex 宿主 bug，用"退出后删目录"兜底）。

`## <vX.Y.Z> · <日期>`；分节：New / Fixed / Changed / Known / 升级提示（需 dsh ≥ 版本）。当前 Known：审批/提问依赖 `$events` 连接，客户端掉线时该轮需取消或由官方页面接续。

## 预览版 dsh（非 npm 正式版）源码调试
> 适用：官方尚未发布 npm 包时，直接用 GitHub 最新源码本地运行/构建/全局使用。
> 前置：Node（^22.19\|\|>=24）+ pnpm；仓库为 pnpm monorepo（根包 private、无 bin，`dsh` bin 在子包 `apps/cli`）。下称克隆到的源码根为 `<源码仓根>`。

```bash
# 0) 前置就绪后，先进入源码根目录 <源码仓根>

# 1) 更新到最新源码
git pull

# 2) 安装依赖（网络慢可配用户级 registry 镜像）
pnpm install

# 3) 本地直接跑（tsx 直跑源码，无需构建；推荐调试方式）
pnpm dsh web --no-open --port 0

# 4) 全量构建（仅在要产出安装/打包产物时做，较重）
pnpm run build

# 5) 全局 link（全局 dsh 的 bin 在子包 apps/cli，勿在根目录 link）
cd apps/cli
pnpm run build          # 先产出 lib/bin.js 及依赖
pnpm link --global      # 之后任意终端可直接 dsh web

# 6) 取消全局 link（必须回到当初 link 的目录 apps/cli）
cd apps/cli
pnpm unlink --global
pnpm list --global      # 验证目标已不在全局列表

# 7) 日常更新本地运行版
git pull
pnpm dsh web            # dev 走 tsx 直跑，无需重构建

# 提醒：
#   - 勿手改全局 node_modules 里的文件，否则构建 / link 会被覆盖
#   - Windows 用 cmd 或 PowerShell 均可
#   - 该版未上 npm，属源码预览；协议面以实际 dsh 版本为准（按 04 核对）
```
