# 10 · 对话区信息块「显示模型与规则」（改前必读，防止反复改错）

> **用途**：这是"每个信息块在哪显示、何时显示、如何显示"的**唯一基准**。改任何一处 UI 前**先读这张表**；
> 若确需改变某个行为，**先改本表 + 涉及文件**，避免再出现"收平铺又折叠、hover又done"这类反复。
> **基线：对齐上游 dsh 0.1.2-rc.1**（`<dsh 源码仓根>/<版本目录>/deepseek-harness` 源码——插件实际对接版本）。
> 过程折叠/思考行/动作条时机/左下角状态行/瀑布流提问交互，**0.1.2-rc.1 均完整支持**（TurnProcessNodeView/ReasoningRow/MessageIconActions/ChatView.deepDiving/ui-user-questions 齐全）。
> 注：`<dsh 源码仓根>/deepseek-harness`(0.1.5-alpha.1) 与本套显示时序逻辑一致，我此前读 UI 样式用的是 0.1.5-alpha.1 副本，**行为基线应以 0.1.2-rc.1 为准**。

## 0. 总原则
上游把一场 assistant 回复拆成 **「过程内容（可折叠收纳）」+「正文（markdown）」** 两部分，且**进行中展开、定稿收起**。
交互类（提问/审批）走**输入框上方 waterfall 弹窗**，不进对话行；对话行只承载**记录**。

## 1. 信息块显示表（权威）

> 上表"过程折叠内 / 展开才见"都指**外层折叠**（`N 次工具调用 · M 条消息`，见 §2.1）**展开后的明细**；明细里每个过程行**各自还有内层 disclosure**（收起一行 / 点开看内容），是两层。

## 2. 关键规则（反复的根源，一旦改动先更新这里）

### 2.1 过程折叠（外层「N 次工具调用 · M 条消息」）

**作用**：把一轮 assistant 回复的"过程"（思考/工具调用/上下文注入/召回/网页搜索获取/提问记录）收进**一个可折叠的汇总头**，避免过程行全部铺开占空间。点开发开看每个过程的 disclosure 行；进行中默认展开（能看到在干嘛），定稿收起为一行计数。

**触发（是否显示折叠头）**：回合过程里有**工具调用项(ask 提问除外)**、或**上下文注入/召回项(context)**、或**定稿计数 toolCallCount/messageCount>0** → 显示 `N 次工具调用 · M 条消息`，空则兜底 `已思考`。
**纯思考**（无注入/无工具/无计数）→ **照常出折叠头**，文案兜底「已思考」——与「N 次工具调用」是同一套折叠，**不是平铺**。上游 `foldable` 对「本回合有过程成员」成立，推理行本身就是过程成员；折叠后思考行同样收进明细里。
【v0.1.7 修正】此前本行写「纯思考不显示折叠头、思考行平铺在前」，与上游不符。

**展开/收起时机**：
- **进行中(pending，turn 未 closed)**：默认**展开**（能实时看思考/工具/注入在动）；左下角 `深度求索中…` 状态行做运行指示（对齐上游 `turnClosed`）。
- **定稿(done)**：**收起**成折叠头 `N 次工具调用 · M 条消息`（`message.turnProcess.*`：`{count} 次工具调用` / `{count} 条消息` / `{count} 个 subagent`，分隔 ` · `，顺序即此）；**三项全为 0 则 `已思考`**(`thoughtForAWhile`)。点开看全部过程行。

**布局/样式**：像素值（折叠头、过程行、明细容器、各行 disclosure）统一登记在 `docs/design/08` §5.0/§5.1/§5.2——**本文档不再重复数值**，避免同一事实两处维护、改一处忘另一处。

**展开后的明细**：过程行**平铺**，各自是 disclosure（收起一行 `标签 · 摘要`，点开看内容）：
- 上下文注入/召回 → `message/ContextInjectionRow`（`上下文注入 · 来源` / `跨会话召回 · 标签`）
- 思考 → `chain/ReasoningRow`（`思考 · 摘要` 一行；流式取 `latestLine` 动态、定稿取 `firstLine`；摘要剥 `**`）
- 工具/终端/web/提问记录 → `chain/ToolRow`（Pwsh→TerminalBlock、web→WebCard、ask→AskCardBody，各自可展开）
  - **收起行的摘要位**三条规则（细则与文件对照见 `09` §2 ④⑤⑥）：**真失败（isError）→ 结果文本首行 + 错误色**（提问行除外）；**非零退出的 shell → 仍是模型写的 `description`**（退出状态是结果数据，不是调用失败）；**文件类工具的路径 → 相对工作区根**（跟上游；工作区外的文件显示全路径，不缩成文件名）。

> ⚠️ 这是**外层折叠**（整体收起/展开），与每个过程行**自身的 disclosure**（各自收起/展开看详情）是两层：外层折叠控制"整包过程"显隐，内层 disclosure 控制"单个过程"内容。

### 2.2 系统提示词的来源与位置（按上游）
上游把它渲染成对话流里的一条 **`system-prompt` 节点**（`ui-chat/conversation-nodes/request-prompt.ts`），规则如下：

- **数据源 = 请求头**：取 `request/header` 事件的 `prompt.system` —— 即**该请求实际发给模型的完整 system**，不是 `agent-instructions` 的 `user/message` 注入事件（后者只是"注入了一份指令文件"，与实际请求的 system 不是一回事）。
- **锚点**：`requestPromptAnchor()` —— step 1 锚到该 turn 的 `turn/start`，其余 step 锚到 `step/start`；已渲染过的保持原锚点（`stableRequestPromptAnchor`）。**即每个回合开头一条**，位置在用户提问之前。
- **显隐 `showsPrompt`**：首次（无 previous）/ `reason !== 'change'` / `startsSeries === true` / system 变更（`change` 为 `system` 或 `system-and-tools`）时为真；`system === ''` 不渲染。
- **展开体**复用上下文注入行的样式与 body（`SystemPromptRow` 与 `ContextInjectionRow` 共用一套）。

**不进回合过程**：`form==='instructions'` 的 agent-instructions 注入在**数据源跳过**（live `src/dsh/stream.ts` 的 `user/message` 分支 + 历史 `src/dsh/session.ts` 的 `getSessionMessages`，两处都判 `contextForm(source) === 'instructions'`），只由上面这条 `system-prompt` 节点承载；回合过程里只留技能目录/召回/插件/notice 等注入。=> 避免"只含它的回合过程展开为空"，也避免**实时冒一行、刷新后又消失**（两侧口径必须一致）【2026-09-11 修正：原文写「live `contextRow`」，该标识符在代码里不存在；且当时 live 侧实际**没有**这道过滤，只有历史侧有】

> **插件实现（2026-09-11 起与上游一致）**：数据源 = 宿主 `src/dsh/stream.ts`（实时）与 `src/dsh/session.ts`（历史）的 `request/header` 分支，取 `header.system`；判据抽在 `src/dsh/official/request-prompt.ts`（`readRequestPrompt` / `requestToolsKey` / `requestShowsPrompt`，与上游一一对应）**实时与历史共用，不各写一份**。位置 = 该行挂在**该回合第一条 user 行**上（实时经协议 `chatSystemLine` **回插**到最近一条 user 行之前，历史经 `HistoryMessage.systemPrompt` 在 user 行前插入）；渲染 = `webview/chat/components/message/SysPromptRow.ts`。**旧的「左上角常驻入口」链路（`SystemPromptEntry` + 宿主 `postSystemPrompt`/`getSystemPrompt` + `chatSystemPrompt` 消息 + store 的 `systemPrompt` 信号）已于同日删除**。

### 2.3 提问分离「交互」与「记录」
- 交互（选/提交/取消/关闭）→ 输入框上方 waterfall 弹窗（`pendingQuestion` 信号驱动）。
- 对话行提问卡只做记录；**提问不参与过程折叠**（`hasFold` 排除 ask_user_question），纯提问 turn 平铺显示问行。

### 2.4 动作条时机
复制/重新生成/用量/用时**仅回答结束后(done)**渲染（不是 hover 常驻——那是上游 `data-actions-reveal`，本插件按用户要求定稿后现）。
