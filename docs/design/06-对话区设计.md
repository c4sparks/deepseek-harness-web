# 07 · 对话区设计（改 UI 前必读）

**★ 三条最容易踩的规范：**
1. **只有「标签(label/tag)」永不换行**（思考/网页搜索/提问/Pwsh/工具标题…）；标签后的正文自适应省略、展开正文可换行（§11）。
2. 过程行（思考/工具）统一 **Disclosure 交互**：收起=单行箭头行、点开看正文（§8.1）。
3. 工具成功(ok) **不打勾**；error 才显红、running 掠光、stopped 琥珀（§8.2）。

## 0. 总原则

上游把一场 assistant 回复拆成 **「过程内容（可折叠收纳）」+「正文（markdown）」** 两部分，且**进行中展开、定稿收起**。
交互类（提问/审批）走**输入框上方 waterfall 弹窗**，不进对话行；对话行只承载**记录**。

## 1. 信息块显示表（权威）

| 信息块 | 在哪显示 | 何时显示 | 如何显示 |
|---|---|---|---|
| 系统提示词 | **对话流内，每个回合开头**（该请求可见消息序列的起点，即在用户提问之前） | 该请求 `showsPrompt` 为真（首次 / `reason!=='change'` / `startsSeries` / system 变更）且 `system !== ''` | 一行可折叠 disclosure：`系统提示词` + 展开看该请求实际发给模型的 system 全文；**不入回合过程**（细则见 §3） |
| 上下文注入 / 跨会话召回 | **过程折叠内** | 展开才见（不单独平铺） | 一行`上下文注入 · 来源` / `跨会话召回 · 标签`，可展开 |
| 思考 | 过程折叠内 | **纯思考也进折叠**（折叠头文案兜底「已思考」，与「N 次工具调用」是同一套折叠）；只有链里**仅含提问行**时才平铺 | 收起一行`思考 · 摘要`(定稿取首行/流式取最新行)，点开全文 |
| 工具(终端/web/提问卡/通用卡) | 过程折叠内 | 展开才见 | 各自卡：终端卡(等宽命令) / web 卡(来源列表) / 提问卡(问答记录) / **通用卡(「输入」「输出」两分区)**，可展开（卡的分派与回退见 §9） |
| 正文(markdown) | 过程折叠**下方** | 流式慢慢出，定稿完整 | markdown，无流式光标(上游无) |
| 动作条(复制/重新生成/用量/用时) | 对话行底部 | **回答结束后(done)**才显示，过程不出现 | 复制/重新生成/用量/用时 |
| 提问**交互** | **输入框上方弹窗**(waterfall) | pending(待答) | 选项/自由输入 + `回答`(选全可提交)/`取消`/`关闭` |
| 提问**记录** | 对话行 | 定稿后 | `提问 · {answered}/{total} 已回答 / 已取消 / 已中断` + 问题↔回复 |
| 左下角状态行 | **左下角** | **运行中(processing)** | `xxxx…` + 小转圈 + ≥15s 时钟 |

> 上表"过程折叠内 / 展开才见"都指**外层折叠**（`N 次工具调用 · M 条消息`，见 §2）**展开后的明细**；明细里每个过程行**各自还有内层 disclosure**（收起一行 / 点开看内容），是两层。

## 2. 过程折叠（外层「N 次工具调用 · M 条消息」）

**作用**：把一轮 assistant 回复的"过程"（思考/工具调用/上下文注入/召回/网页搜索获取/提问记录）收进**一个可折叠的汇总头**，避免过程行全部铺开占空间。点开看每个过程的 disclosure 行；进行中默认展开（能看到在干嘛），定稿收起为一行计数。

**触发（是否显示折叠头）**：回合过程里有**工具调用项(ask 提问除外)**、或**上下文注入/召回项(context)**、或**定稿计数 toolCallCount/messageCount>0** → 显示 `N 次工具调用 · M 条消息`，空则兜底 `已思考`。
**纯思考**（无注入/无工具/无计数）→ **照常出折叠头**，文案兜底「已思考」——与「N 次工具调用」是同一套折叠，**不是平铺**。上游 `foldable` 对「本回合有过程成员」成立，推理行本身就是过程成员；折叠后思考行同样收进明细里。
【v0.1.7 修正】此前写「纯思考不显示折叠头、思考行平铺在前」，与上游不符。

**计数（三项）**：顺序即上游 `TurnProcessNodeView` —— `{count} 次工具调用` / `{count} 条消息` / `{count} 个 subagent`，分隔 ` · `；**三项全为 0 兜底 `已思考`**（上游 `thoughtForAWhile`）。
- **两项计数互斥**：subagent 委派**不计入** `toolCallCount`，单独计数，合起来是本回合全部工具调用。此前 `subagentCount` 完全缺失，导致纯 subagent 回合显示成「已思考」、且进行中/定稿文案会在两个值间跳。

**展开/收起时机**：
- **进行中(pending，turn 未 closed)**：默认**展开**（能实时看思考/工具/注入在动）；左下角状态行做运行指示（对齐上游 `turnClosed`）。
- **定稿(done)**：**收起**成折叠头。点开看全部过程行。

**展开后的明细**：过程行**平铺**，各自是 disclosure（收起一行 `标签 · 摘要`，点开看内容）：
- 上下文注入/召回 → `上下文注入 · 来源` / `跨会话召回 · 标签`
- 思考 → `思考 · 摘要` 一行；流式取最新行（动态）、定稿取首行；摘要剥 `**`
- 工具/终端/web/提问记录 → 各自卡可展开（终端卡等宽命令 / web 卡来源列表 / 提问卡问答记录 / 通用卡「输入」「输出」两分区）
  - **收起行的摘要位**三条规则（细则见 §10）：**真失败（isError）→ 结果文本首行 + 错误色**（提问行除外）；**非零退出的 shell → 仍是模型写的 `description`**（退出状态是结果数据，不是调用失败）；**文件类工具的路径 → 相对工作区根**。

**仅当链里只剩提问行**时才不折叠（提问不参与过程折叠，`hasFold` 排除 ask_user_question，见 §4）。

**布局/样式**：像素值（折叠头、过程行、明细容器、各行 disclosure）统一登记在 `07` §5.0/§5.1/§5.2——**本文档不重复数值**，避免同一事实两处维护。

> ⚠️ 这是**外层折叠**（整体收起/展开），与每个过程行**自身的 disclosure**（各自收起/展开看详情）是两层：外层控制"整包过程"显隐，内层控制"单个过程"内容。

## 3. 系统提示词的来源与位置（按上游）

上游把它渲染成对话流里的一条 **`system-prompt` 节点**：

- **数据源 = 请求头**：取 `request/header` 事件的 system —— 即**该请求实际发给模型的完整 system**，不是 `agent-instructions` 的 `user/message` 注入事件（后者只是"注入了一份指令文件"，与实际请求的 system 不是一回事）。
- **锚点**：每个回合开头一条（step 1 锚到该 turn 的 `turn/start`，其余 step 锚到 `step/start`；已渲染过的保持原锚点）。位置在用户提问之前。
- **显隐 `showsPrompt`**：首次（无 previous）/ `reason !== 'change'` / `startsSeries === true` / system 变更（`change` 为 `system` 或 `system-and-tools`）时为真；`system === ''` 不渲染。
- **展开体**复用上下文注入行的样式与 body（上游两者共用一套）。

**不进回合过程**：`form==='instructions'` 的 agent-instructions 注入在**数据源跳过**，只由上面这条 `system-prompt` 节点承载；回合过程里只留技能目录/召回/插件/notice 等注入。=> 避免"只含它的回合过程展开为空"，也避免**实时冒一行、刷新后又消失**（实时与历史两侧口径必须一致）。

## 4. 提问分离「交互」与「记录」

- 交互（选/提交/取消/关闭）→ 输入框上方 waterfall 弹窗（`pendingQuestion` 信号驱动）。
- 对话行提问卡只做记录；**提问不参与过程折叠**（`hasFold` 排除 ask_user_question），纯提问 turn 平铺显示问行。

## 5. 动作条时机

复制/重新生成/用量/用时**仅回答结束后(done)**渲染（不是 hover 常驻——那是上游 `data-actions-reveal`，本插件按用户要求定稿后现）。

## 6. 行类型与组件分层

行类型共六种：user / context / assistant / approval / question / notice；assistant 行挂扁平 `chain[]`(reasoning/tool 交错)。

组件按行类型分两大类：消息行归 `webview/chat/components/message/`，回合过程行（思考/工具/上下文注入）归 `webview/chat/components/chain/`。编排壳只做挂载，不再堆积行渲染；消息列表按 `row.kind` 分派并负责智能滚动。

数据模型在 `webview/chat/core/store/`：装配层只建切片、注入跨切片依赖、聚合 `reset`、显式装配 `ChatStore`，行为全部在切片里。切片之间**无 import 边**，跨切片依赖一律由装配层以实例注入；`ChatStore` 是对外契约，组件消费者零改动。架构框图见 `02` §整体架构。

| 切片 | 职责 |
|---|---|
| types | 行类型与 `ChatStore` 接口 |
| messages | 消息行模型：列表、正文流式、过程归约、通知行、审批行 |
| composer | 输入区：文本 / 图片 / 附件 / @引用贴片 + 取消 / 复制 / 选文件 |
| selectors | 权限 · 模型 · 模式的选项状态与弹窗 |
| catalogs | 「/」命令目录与「@」候选的拉取与到达 |
| question | 提问弹窗 |
| status | 过渡态 / 统计行 / plan / goal |
| history | 历史恢复：快照重放为对话行 |
| outbox | 用户发起的发送动作：发送 / 建议 / 重新生成 |
| reducer | 宿主消息归约器：消息类型到切片方法的唯一分发点 |

## 7. 状态体系与维护约定

**单一来源**：对话区状态字面量（思考/生成/占位/打字/过渡/任务工具/过程/终态等）只在 `webview/chat/core/states.ts` 出现一次；组件 import 使用；未接线项不预留死代码。

- 加一种"对话区出现的块" → 新增/归属到对应行组件 + 在消息列表分发；过程行（思考/工具/上下文注入）走过程组件目录。
- 样式按功能模块化：`styles/` 下按过程折叠、状态、消息、composer 分文件，入口样式文件以 `@import` 引入子模块；继续拆分沿用同一方式。不要为了小改重排大文件。

## 8. 行级 UI / 交互规格（实现按此对齐）

### 8.1 过程行（Disclosure 统一交互）

所有过程行（思考/工具）是同一套 Disclosure 形态：**收起 = 单行头部（箭头 + 图标 + 标题 + 状态），点行/箭头展开正文**。

| 成员 | 收起(单行) | 展开 | 流式中 |
|---|---|---|---|
| 思考行 | "思考 + 首段一行(宽不足省略)"；摘要**剥掉 `**`** | 全文（不剥，原样） | 默认自动展开、独立容器(高封顶)自动滚底；定稿后可再收起 |
| 工具行 | "图标 + 标题(Pwsh/网页获取/…) + 摘要(单行自适应) + 状态"；无专属标题的工具标题为「工具调用」，真实工具名在摘要里 | 按卡体分派：终端卡 / web 卡 / 提问卡；**其余走通用卡**——"输入"(调用参数 pretty JSON) + "输出"(调用结果) 两个带标签分区，中间一条 hairline | running 时行上掠光带（见 §8.2） |
| 过程折叠头 | 进行中：动词轮换；定稿：`N 次工具调用 · M 条消息` 折叠行 | 点击展开所有过程行 | 定稿默认收起，可再展开 |

> 摘要剥 `**` 是**有意偏离 0.1.2-rc.1 基线**（rc1 保留 `**`，0.1.5-alpha.1 才剥）：纯前端观感取舍，不影响服务端；两种都行，当前跟的是剥掉。

### 8.2 行状态标记（leading 二选一）

上游行里只有**一个** leading 位，由 `leadingFor(state, icon)` 决定：

| 态 | 显示 |
|---|---|
| `error` | 状态点（红） |
| `stopped` | 状态点（琥珀） |
| 其余（含 running/ok） | **变体图标** |

**行尾没有状态标记**。「行首恒显图标 + 行尾角标（转圈/⚠/空心圆）」是自造结构，已废止。**ok 无角标**（成功完成本身不打勾，避免无意义绿勾）。状态点按上游 `StateDot` 为**两层结构**（整圆 halo + inset 20% 实心内核）。

**④ shell 失败的整行覆盖**：上游 `state = model.state === 'ok' && terminalFailed(terminal) ? 'error' : model.state`，其中 `terminalFailed = !running && (exitCode !== 0 || signal !== undefined)`。**非零退出/被信号终止的 shell 调用，调用本身 `isError: false`**（退出状态是结果数据，不是调用失败），靠这条覆盖才让整行变红。

- 覆盖落在终端卡的 card model（`TermCard.state`），行与卡内状态点/文案取**同一个值**（原先行按 `item.status` + 覆盖、卡只按退出码，两处各判一次）。
- **补漏**：调用**真失败**（isError、无退出码）时，卡内曾按"没有退出码 = 干净退出"判成"已完成 + 绿点"，与行上红点矛盾。上游遇 isError 不出终端卡（退回通用卡），故上游无此问题；本插件有意留用终端卡（见 §9），失败态便由卡自己如实表达：`error` → 失败 + 红点，`stopped` → 已停止 + 琥珀点。

**① 关于 ok 态**：上游 `leadingFor` 对 `ok`/`running` 返回的是**变体图标**（不是绿点）；绿点只在个别卡内出现。做这块时按上游源码定，**不按截图猜**。

**② running 的表示**：**行上的一道掠光带**（`[data-state='running']::after` + keyframes，2.6s），不是转圈。宽度适配要点：带子**固定 300px、位移用 `left` 而非 `transform`**——起点 `-300px` 是绝对像素（整条带子在行外），终点 `100%` 相对行宽；用 `width: 40%` 或 `translateX(350%)`（相对自身宽的百分比）会让窄栏光带缩成一条、宽栏拉成一大片。

**③ 无障碍文字**：点与掠光都是 colour-only、对 AT 不可见，另配视觉隐藏的 `运行中/失败/已停止` 文字供播报。

**不做**：换图标集。上游 leading 用内联 SVG，插件全用 codicon；换图标集是**全局**独立工作（需引图标资源），不属本条。

### 8.3 非过程行的消息行

| 行 | 交互要点 |
|---|---|
| user | 右侧气泡；meta 仅复制(无重生成) |
| assistant | 上方回合过程；正文流式光标；末 meta 复制/重生成/用量/用时(定稿后现，见 §5) |
| approval | 允许/拒绝按钮，应答即删卡 |
| question | 选项/自由输入 + 回答/取消；取消先禁用等宿主确认再删 |
| notice | 命令结果：失败红点红字/成功常规色 |

### 8.4 过渡/占位

- 恢复历史/切工作区：宿主恢复前发 `busy:loading`，输入区透明禁输入并显示转圈提示；恢复后清空。
- 欢迎/placeholder/斜杠 ghost 沿用既有。

### 8.5 视觉基调

hairline 边框 + 低透明叠层(深浅通吃) + 语义色状态点 + 克制 hover；回合过程/思考/工具行字体层级：标题加粗、内容次级淡字；参数值等宽可滚动。**像素级数值（宽/高/间距/上下左右 padding/margin/圆角/字号/行高/动效）见 `07`。**

## 9. 工具卡：分派与回退

分派顺序按上游瀑布：**提问 → 终端 → 差异 → 读文件 → 搜索 → web → 通用**。

分类、图标与标题一律取自上游：变体按上游 `TOOL_VARIANTS` 表（bash/read/search/write/edit… 各自对应图标与标题），标题用 i18n 字典 `tool.title.*`（zh 值照抄），文案从上游 `ui-conversation` zh 字典原文抄录（不自造）；**未知工具回通用标题「工具调用」**，真实工具名由摘要承载。

| 卡 | 触发工具 | 数据来源 | 回退条件 |
|---|---|---|---|
| 终端卡 | bash/pwsh/shell 类 | 命令与 cwd 取自 `tool/call` 的 arguments；exitCode/signal 取自结果**末尾 marker**（非独立 JSON 字段） | 见 §8.2 ④（失败态由展示层覆盖） |
| 差异卡 | `write`/`edit`/`str_replace_editor` | 优先结果 `meta.diffs`；`write` 在 meta 缺失/空时回退**参数推导的整文件差异**（故 write 必出卡） | `edit` 缺 `meta.diffs` 即回退通用卡；`str_replace_editor` 定稿不出卡 |
| 读文件卡 | **只认 `read`**（`read_image`/`readTextFile` 不给，上游同） | `meta.{path,totalLines,lines,lang}`；结果文本只用于校验上游 read 信封正则，正文不进卡 | 形状不符回退通用卡 |
| 搜索卡 | `grep`/`glob` | `meta.{shape,truncated,total,files}` 或 `meta.paths`；截断时附结果文本作定位符 | 形状不符回退通用卡 |
| web 卡 | `web_fetch`/`web_search` | `tool/result.data.meta`（宿主补齐捕获） | 无 meta/畸形回退通用卡 |
| 通用卡 | 其余 | 「输入」（参数 pretty JSON）+「输出」（结果）两分区，各带标签 | — |

**出卡时机**：专属卡只在终态 `ok` 出（差异卡另有 running 态）；**形状不符一律回退通用卡，零回归**。

**长内容折叠**：三张专属卡（差异/读/搜索）按上游 **8 行上限折叠中间**（首尾各半 + 「… 其余 n 行」）；搜索卡另有**文件头按钮**做第二层折叠。**终端卡不折叠**——它用 224px 上限 + 纵向内滚（见 `07` §5.4）。

**未做**：收起行文件路径可点击打开（需新增 webview→宿主通道 + `vscode.open`）；读文件卡的 `~` 家目录缩写（插件无 home 数据）。

## 10. 收起行的摘要规则

### 10.1 ⑤ 失败行的收起摘要

上游规则：

```
errorSummary = state === 'error' && output !== null ? firstLine(output) : null
failureLine  = state === 'error' ? errorSummary : null
summaryText  = failureLine ?? terminal?.description ?? summary
```

注释原话：A failure must replace, not supplement。渲染时该行摘要着错误色。

**关键分界（一度搞错）**：`state === 'error'` 是**宿主按 isError 判出的终态**，**不是**展示层那条 `terminalFailed` 覆盖出来的红。**非零退出/被信号终止的 shell 调用 `isError: false`**，其 `failureLine` 为 null，**摘要位仍是模型写的 `description`**（上游亦然；「失败」由行首红点 + 卡内退出码 Pill 表达）。只有**真失败（isError）**才把摘要位换成结果首行。

- **提问行不换**：上游 `AskQuestionRow` 调 `ToolRow` 时不传 `errorSummary`，提问行永远保留自己的摘要。
- **首行取法**：切到第一个换行符为止、**不 trim**（上游同）；结果为空串 → 落回描述；首行为空行 → 摘要位整体不显示。
- **裸错误码不显示**：上游从不显示错误码，插件自造的裸错误码节点已删除。

### 10.2 ⑥ 文件类工具的收起摘要

上游给的是 `abbreviateHomePath(relativizeToCwd(deriveSummary(...), cwd), home)`。**Windows 上 `abbreviateHomePath` 是空操作**（只缩 POSIX 家目录），故两侧等价于 `relativizeToCwd`：**工作区内的文件 → 相对路径；工作区外 → 原路径全显、不缩成文件名**。

- **不做 basename**：曾按「收起行只显文件名」改过一版，**已回退**——口径统一为跟上游。basename 只出现在上游的产出文件 chips（本插件未实现该功能）。
- **只涉及收起行，卡片内部路径不同**：读卡横幅 = 相对工作区根（上游同）；**差异卡文件头 = 工具给的原路径**（上游明确 verbatim）；搜索卡文件路径 = 原样（上游不 relativize）。

## 11. 排版硬规则

- **「标签(label/tag)」永不换行**：指标识类型的短词（思考 / 提问 / 上下文注入 / Pwsh / 网页搜索 / 工具标题…）作为整体不可断词/折行。涉及标题、工具标题、摘要文本等标签类元素。
- **收起态：标签后的正文默认显示一行**（不做整段折行/全显），占满剩余宽度，**宽度不足才省略(ellipsis)**、不做固定字数上限——编辑器/宽面板一行能容更多就显示更多；**全文一律靠展开箭头查看**。右侧状态/错误码固定。
- **展开的正文/参数允许换行**（可读区域内折行；JSON 可横向滚动）。约束只针对"标签不换行"，不限制正文。
- 收起行单行由标签 + 自适应正文共同构成（标签不换 + 正文省略），不会把标签挤断。
