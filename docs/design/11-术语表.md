# 11 · 术语表

> 阶段：总则 · 维护者：插件维护者
> 覆盖：对话区核心概念的中英术语、上游原名、本插件代码标识符，以及标识符命名前缀规则。改代码或文档用词前先查本表。

## 1. 用途与范围

同一概念此前在文档与代码里有多个叫法（「过程链」「过程折叠」「折叠窗口」「链」指的是同一个东西），改一处容易踩到另一处，也难与上游源码对照。本表把**每个概念只保留一个中文词、一个英文原名**，并指明对应的插件标识符。

范围只到对话区（回合过程及其成员、工具行）。协议层（RPC 信封、鉴权、会话域）术语见 `04-dsh协议耦合与升级`。

## 2. 命名前缀规则 【v0.1.7 · dsh 0.1.2-rc.1】

| 规则 | 说明 |
|---|---|
| 加前缀 | `dsh` / `Dsh` 前缀标记「形状照搬上游、与上游关联度高」的标识符（类型用 `Dsh`，字段/函数用 `dsh`） |
| 不加前缀 | 插件自身的 UI 组件、页面、功能标识符一律不加——为后续适配其它后端、以及插件独有功能留出命名空间 |
| 注释 | 注释里不写 dsh 字样 |
| 与 00 §4.3 的关系 | 00 §4.3 禁的是**版本**前缀（如 `rc1WorkspaceList`）；本表的来源前缀（`DshTurnProcessItem`）不受该条约束，两者不冲突 |

当前带前缀的标识符（仅这两个，本次新增）：

| 现名 | 位置 | 旧名 |
|---|---|---|
| `DshTurnProcessItem` | `webview/chat/core/store/chat.ts` | `ChainItem` |
| `DshHistoryTurnProcessItem` | `webview/chat/core/protocol.ts`、`src/dsh/session.ts`（各一份） | `HistoryChainItem` |

其余对话区标识符（`ChatRow`、`ToolVariant`、`argsRaw`、`Chain` 组件、`chain/` 目录、`chain.css`）**保持原名**。

## 3. 回合过程与其成员

| 概念 | 英文原名 | zh 文案 | 本插件标识符 / 文件 |
|---|---|---|---|
| 一次助手回合 | Turn | `{turns} 轮 · {steps} 步` | `ChatRow` 的 assistant 行 |
| 回合过程（过程内容整体） | Turn process / `turn-process` | 无整体文案，用子计数拼接 | `DshTurnProcessItem[]`，挂在 `ChatRow.chain` |
| 过程折叠（折叠控件与交互） | process disclosure / `foldable` | 折叠头文案见下 | `components/chain/Chain.ts` |
| **折叠头**（外层折叠的触发器：一行计数，单击展开/收起整包过程明细） | process disclosure header / control（上游 `TurnProcessNodeView`，自述 "Turn-level process disclosure controller"） | 有计数 `{count} 次工具调用 · {count} 条消息`；**计数全为 0 时兜底「已思考」** | `Chain.ts` → `.chain-summary`，文案变量 `foldLabel` |
| 过程行（折叠内单个成员） | process row | 各自见下 | `DshTurnProcessItem` 联合的成员 |
| 折叠头计数 | `toolCallCount` / `messageCount` / `subagentCount` | `{count} 次工具调用` / `{count} 条消息` / `{count} 个 subagent`，分隔 `  ·  ` | `Chain.ts` 的 `foldLabel` |
| 无计数的兜底 | `thoughtForAWhile` | 已思考 | 同上。**纯思考回合也出折叠头**，文案即此兜底——与「N 次工具调用」是同一套折叠，不是平铺 |
| 答案（定稿正文） | answer（`answerStep` / `answerAnchorSeq`） | 无 | `ChatRow` assistant 行的 `text` |
| 思考段 | reasoning | `message.think` 思考 | `kind: 'reasoning'`，`components/chain/ReasoningRow.ts` |
| 上下文注入 | context injection | `message.contextInjection` 上下文注入 | `kind: 'context'`，`components/message/ContextInjectionRow.ts` |
| 跨会话召回 | context recall | `message.contextRecall` 跨会话召回 | 同上（`provenance.role === 'recall'`） |
| 系统提示词 | system prompt | `message.systemPrompt` 系统提示词 | `components/message/SystemPromptEntry.ts`（不入回合过程） |
| 子智能体 | subagent | `{count} 个 subagent`（上游不译） | **已单列**：`subagentCount`，与 `toolCallCount` 互斥（subagent 委派不计入工具调用数）。实时 `stream.ts` 与历史 `session.ts` 同口径 |

> **两层折叠，别混**：**折叠头**是**外层**——把整包过程（思考/工具/注入）收成一行计数，单击展开/收起；**过程行各自还有内层 disclosure**——收起时自己是一行 `标签 · 摘要`，点开看自己的内容。
> 说话时请指明是哪一层：「折叠头」= 外层那一行；「过程行展开/收起」= 内层。只说「展开」会导致改错组件（`Chain.ts` ↔ `ReasoningRow.ts`/`ToolRow.ts`）。

**工具行终态的判定**（易错，【v0.1.7 修正】）：

| 情况 | 终态 | 依据 |
|---|---|---|
| 正在调用 | `running` | — |
| `error.code === 'interrupted'`（回合被打断） | **`stopped`**（琥珀，非失败） | 特例优先于 isError |
| 其余：`isError === true` | `error` | **主依据是 `isError`，不是「有没有 error.code」** |
| 其余：`isError !== true` | `ok` | 同上 |
| `ask_user_question` 且 `code === 'ASK_CANCELLED'` | **`ok`**（用户自己取消，**无任何错误标记**） | 展示层覆盖：上游 `AskQuestionRow`，本插件 `webview/chat/core/ask-card.ts` |
| `ask_user_question` 且 `code === 'ASK_ABORTED'` | **`stopped`** | 同上 |

> `error.code` 是**开放集合**，其中若干并不表示失败（上表三个）。按「有码即失败」判会把「用户取消提问」「回合被打断」一律标成红色 + ⚠ + 裸错误码——这是修过的实际 bug。通用判定只有一份实现（宿主 `tool-status.ts`，实时/历史共用）；两个提问码按上游分层放在展示层覆盖。

展平规则（对齐上游 `resultText()`）：内容块中 `type` 为 `text` 的原样输出，**其余块序列化为 pretty JSON**（内容块类型可被插件扩展，非 text 块没有通用渲染法）；内容为空且带结构化错误时兜底 `error.name: error.code` 一行。

**载荷层级**（曾读错，2026-09-10 修正）：`tool/result` 的展示内容在 `data.message.content[0].content`——`content[0]` 是 `tool-result` 包装块，真正的 `ContentBlock[]` 在它里面；配对 id 在 `data.message.source.callId`，**顶层没有 `callId`**。解包统一走 `src/dsh/official/result-text.ts readToolResult()`，并兼容迁移前「顶层 `callId` + 扁平 `content`」的旧格式。

## 6. 已知缺口

| 缺口 | 说明 |
|---|---|
| 「Chain」字样残留 | `Chain` 组件、`chain/` 目录、`chain.css`、`AskChainItem`（`components/chain/AskCardBody.ts`）仍用 Chain 命名，本次未改。术语上它们承载的是「回合过程」 |
| 跨进程类型手抄两份 | `ViewActivity`（webview）与 `DshActivity`（宿主）形状相同但各自命名；`DshHistoryTurnProcessItem` 在 `webview/chat/core/protocol.ts` 与 `src/dsh/session.ts` 各定义一次；`TurnCounts` 两侧共四份定义。无共享模块，存在漂移风险。**该缺口等 `06-可复用Chat组件化边界` Stage1（ChatClient adapter + 中立 schema）一并解决**——现在做共享会与该文件 §4「dsh 协议永不进入组件源码」相悖，把待拆的耦合焊死 |
| UI 文案未对齐上游 | 未知工具的标题仍回显原名，上游为「工具调用」（`tool.title.generic`） |
| 未采用 toolview 注册表 | 上游按 `tool.call.toolview` 注册表分发，本插件在 `ToolRow` 内联裁决三种卡体 |

## 7. 维护提示

- 新增对话区概念时，先在本表登记中文词 + 英文原名，再落到代码；不要另起同义词。
- 判断某标识符是否该加 `Dsh` 前缀，看它是否照搬上游形状；插件自有的一律不加。
- 上游升级后，本表 §5 的出处文件与 §3/§4 的文案键值需一并复核。
