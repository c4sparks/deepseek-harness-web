# 02 · 架构与运行机制

> 阶段：设计 · 维护者：插件维护者

## 分层
单向依赖 UI → 服务 → API，UI 可换、协议可换。

| 层 | 载体 | 职责 | 可替换 |
|---|---|---|---|
| 装配 | 宿主装配模块 | 命令/面板/桥接 | 只加命令 |
| UI | 聊天页（`webview/chat/`）、宿主网页面板 | 聊天、内嵌 dsh 网页 | 可整体换 |
| 服务 | `src/api/dshService.ts` | dsh 进程/会话/对话编排 | 稳定接口 |
| 事件 | 协议层事件模块 | 事件监听流与应答回传 | 只依赖协议门面 |
| API | 协议层 `src/dsh/` | dsh 协议（信封、连接、会话、流式、网页代理、会话模式） | 换后端只改 `src/dsh/` |

## 整体架构
聊天 UI 与扩展宿主是两个进程内各自打包的独立产物，只经 `postMessage` 通信；消息契约单一来源在 webview 侧的协议模块，宿主侧无同名类型。一轮对话的往返（发送、宿主转发至 dsh、事件回流实时与历史两条路径、webview 归约）产物是同一份过程链。

## 服务层接口（聊天 UI 依赖）
| 类别 | 方法 | 说明 |
|---|---|---|
| 通用 | call(method, payload) | 任意 dsh API |
| 进程 | ensureRunning / dispose | 启动/复用/回收；ensureRunning 单飞，并发入口共享同一次启动 |
| 会话 | getSession / newSession / ensureCurrentWorkspace / ensureWorkspaceForFolder | 会话与当前工作区 |
| 工作区 | listWorkspaces / createWorkspace / listWorkspaceSessions / restoreSession | 枚举/新建/恢复 |
| 对话 | ask / askStreaming / approvalResponse / answerQuestion / cancelQuestion | 发送/流式/审批/提问/停止 |
| 模型/权限 | listModels / selectModel / setPermissionPreset | 模型/权限 |
| 投影 | getProjections | 上游投影 |

上游网页面板（`src/dshPanel.ts`）经服务层启动/复用 dsh 进程；关闭面板只回收本地代理，不回收 dsh 进程。

## 技术选型
VS Code 扩展（vscode>=1.110，node ^22.19\|\|>=24）+ 原生 webview(无框架) + esbuild(产物 dist/extension.js) + scripts/build-chat.mjs(产物 dist/chat) + 本机 HTTP JSON-RPC + `/api/remote.mux` WS + 会话归 dsh + 仅 `globalState['dsh.usage']` 持久化。无数据库。

## 动态识别
- 连接模型：端点含 port 与 authUrl，默认 3080；所有传输从当前端点取端口。
- 启动与端口发现：优先探测既有实例并复用；未命中则检查 Node 后自启（固定 `web --no-open --port 0`，可经 `dsh.webArgs` 追加 `--host`/`--trusted-host` 等调试参数），从 stdout 解析带 token 的地址并验信封；90s 未就绪报 stderr 末行并回收，超时回退 3080。手动实例通常拿不到 authUrl、无法自动登录，因此建议 `dsh.port=0` 由插件自启。
- 握手探测：只读会话列表接口，按响应区分可达（含版本差异）/ 需鉴权 / 端口非 DSH / 未运行。
- 事件投影：上游事件名集中在常量与判别映射各一处，上游改名只改该处。
- 鉴权：上游自 v0.1.2-rc.1 起对 `/api`、WS、网页 `/` 都要求 cookie；webview iframe 存不住该 cookie，内嵌面板走本地认证代理（扩展进程持 cookie，转发 HTTP/WS 到真实端口），外部浏览器直接用带 authUrl 的地址。
- 面板代理：只监听 127.0.0.1 随机端口；面板全部关闭只回收代理端口，dsh 进程保留到扩展停用；上游 401 自动重新登录并重试，仍失败给可读错误页而不铺上游裸 401。

## 降级
| 场景 | 路径 |
|---|---|
| RPC 可用 | 自绘聊天 / 上游页本地代理 |
| RPC 不可用 / 鉴权失败 | 报错并引导在浏览器打开 `endpointAuthUrl()` |

## 可插拔
| 层 | 可插拔点 | 机制 |
|---|---|---|
| UI | 聊天整体可换 | 只依赖 DshService |
| 能力 | mux/流式/审批/提问 | `DshCapabilities{mux,streaming}` 门控 |
| 协议 | 后端可换 | 只改 dsh/ 下模块 |

复杂 UI 单元按 `ChatFeature{id,mount,unmount,enabled}` 注册；能力门控读 capability、配置门控读 dsh.port/cliPath/repoPath、危险功能 danger-full-access 需确认。新能力流程：dsh/ 加方法 → dshService 封装(读 capability) → UI 加 feature(读 enabled) → 可选加配置。

## 关键设计点
共享会话（右键/对话/网页同一线）；当前工作区 = 工作区跟随快照 `updatedAt` 最新（不另存）；新建会话必须归属工作区（显式选 / 当前 / 自动默认），三者皆无抛 `DshNoWorkspaceError`，不再回退 `createSession({})` 的「未分组」【v0.1.7 · dsh 0.1.2-rc.1】；视图重建握手（webview 发 ready 后扩展再推 chatInfo）。
